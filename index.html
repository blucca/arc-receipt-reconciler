Receipt Reconciler.

One transaction can pay many people. Reconcile the individual receipts, keep the evidence, and confirm what each payment belongs to.

Your invoice CSV stays in this browser. No analytics, third-party scripts, uploads, signing, or payments. RPC requests happen only when you click a fetch button.

Amounts are exact decimal strings. Timestamps require UTC Z.

2. Receipt evidence

Arc emits both a canonical system event (18 decimals) and, for ERC-20 calls, a 6-decimal mirror. This adapter uses only the system event, so one payment is never counted twice.

Fetch public Arc mainnet data (optional)

The RPC provider sees the requested public address / block range / transaction hash, never your invoice CSV. Network identity is checked before reads.

Maximum 1,000 blocks per range. Fetching replaces the current transfer evidence. These are read-only requests; no gas is spent.

Imported JSON is unverified input. Only canonical system events belong in Arc input; JSON alone cannot establish token provenance.

3. Review and attribute

A matching amount is a candidate, not proof of business attribution. Select the receipts you recognize, then explicitly confirm their invoice allocation. Partial payments remain partial. A receipt can belong to only one invoice.
